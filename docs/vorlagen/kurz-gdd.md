# Шаблон: Kurz-GDD (мини-геймдизайн-документ) для приложений конструктора

Одна страница на идею. Заполненный Kurz-GDD — это одновременно черновик для
разработки, заготовка грантовой заявки (поля соответствуют вопросам BzKJ) и
вход для Kindertest. Скопируйте блок ниже в `apps/<name>/GDD.md`.

```markdown
# <Эмодзи> <Рабочее название> — Kurz-GDD

## 1. Феномен / потребность (Warum)
Какому явлению отвечает: <глава Gefährdungsatlas / статья UN-KRK / критерий
fragFINN / стандарт ЕС>. Что сейчас происходит с ребёнком без этого приложения.

## 2. Игрок и обещание (Wer + Kernerlebnis)
Возраст: <6-8 / 8-12 / 13-15 / Eltern / Betreiber>. Одно предложение:
«Ребёнок в роли <роль> делает <действие> и уходит с <умение/инсайт>».

## 3. Движок и петля (Wie)
Движок: <quiz-kern / szenario / simulator / planer / beteiligung / katalog / новый>.
Основная петля (3-5 шагов): <например: ситуация → выбор из 3 ходов →
объяснение → следующая ситуация → ранг>.
Что делает петлю реиграбельной: <перемешивание, банк ×2 от раунда, уровни>.

## 4. Lernziele (проверяемые!)
1. Ребёнок может <распознать/объяснить/применить> ...
2. ...
3. ...
(Формулировать так, чтобы Kindertest мог подтвердить: «покажи», «объясни своими словами».)

## 5. Контент-план
Единица контента: <вопрос/сценарий/тема>. MVP: <N> единиц. Схема данных:
<поля JSON>. Дидактический анти-шаблон-тест: <какое правило балансировки —
например, каждый тип ответа где-то лучший>.

## 6. Политика соответствия (Pflicht, docs/02)
[ ] Werbefrei / без покупок  [ ] Без аккаунтов и персональных данных
[ ] Без внешних запросов (CSP self + NetzwerkWaechter)  [ ] localStorage: только
<что именно> + кнопка удаления  [ ] Privacy by default (ноль запросов привилегий)
[ ] Mobile First 360px/48px  [ ] Vorlesen  [ ] Offline после загрузки
[ ] eltern.html  [ ] Impressum/DSGVO перед публикацией
Особые риски темы: <например: тема чувствительная → формулировки без драстики,
адрес помощи 116 111, партнёр-медиапедагог?>

## 7. Стандарты и финансирование (Wofür)
Стандарты: <DSGVO Art. 8 / JMStV / DSA / BFSG-EAA / AI Act / UN-KRK / fragFINN>.
Förder-Fit: <BzKJ (какой фокус) / NRW Games 80% / премия / —> (см. foerder-navigator).

## 8. Аджайл-оценка
Aufwand: <S = контент-пак (дни) / M = приложение на готовом движке (недели) /
L = новый движок (месяцы)>. Что переиспользуем: <пакеты/движки>.
Первый срез (playable): <что именно должно работать через неделю>.

## 9. Kindertest-гипотезы
Что проверяем на 5-8 детях: <понимают ли без помощи? где скучно? что
пересказывают своими словами?> (протокол — docs/05, метод 5).
```

## Правила работы с шаблоном

1. **Не начинать код без п. 1 и 4** — приложение без феномена и проверяемых
   целей не пройдёт ни Kindertest, ни грантовое жюри.
2. **П. 6 не сокращать** — это наша политика docs/02 в форме чек-листа; пункт,
   который «не применим», помечается «n/a + почему», а не удаляется.
3. Заполненный GDD кладётся в папку приложения (`apps/<name>/GDD.md`) и живёт
   с ним; изменения фиксируются как обычные PR.
4. Для контент-паков (typ S) достаточно пп. 1, 4, 5 — остальное наследуется
   от родительского приложения.
