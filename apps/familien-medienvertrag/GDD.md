# 📜 Familien-Medienvertrag — Kurz-GDD

## 1. Феномен / потребность (Warum)
Какому явлению отвечает: медиавоспитание в семье. Медиапедагогика рекомендует
семейные соглашения о пользовании устройствами (Mediennutzungsvertrag) как
базовый инструмент; UN-KRK закрепляет право ребёнка на участие в касающихся его
решениях (ст. 12), JuSchG/Gefährdungsatlas BzKJ описывают риски (экранное время,
покупки, шерентинг). Источник идеи: docs/09, позиция №25 Топ-30. Что происходит
без приложения: правила либо не проговариваются вовсе, либо спускаются «сверху»
как запреты — и потому не соблюдаются; либо семья ставит контролирующий софт с
аккаунтами и слежкой. Договор вбирает вариант Mediennutzungsvertrag вокруг
`takt-pause`.

## 2. Игрок и обещание (Wer + Kernerlebnis)
Возраст: Eltern + Kind (6–12) вместе. Одно предложение: «Семья в роли двух
равноправных сторон выбирает из блоков-правил договор и уходит с подписанным
обоюдным соглашением — где обязательны и правила для родителей».

## 3. Движок и петля (Wie)
Движок: neu — «Baustein-zu-Druckvorlage-Generator» (форма → печатный документ),
родня — Erwachsenen-Werkzeуг `kriterien-check` (чекбоксы + отчёт) и печатный
паттерн `kita-wochenplaner` (`druck.css`, `window.print()`). Основная петля:
отметить правила галочками (kind / eltern / gemeinsam) → дописать своё правило →
вписать имена → живой предпросмотр договора → печать/PDF с линиями для подписи.
Реиграбельность: договор пересматривается на еженедельном Kurz-Check и меняется.

## 4. Lernziele / Nutzwert (проверяемые!)
1. Семья может **назвать** минимум по одной обязанности каждой стороны — ребёнка
   И родителей (симметрия договора).
2. Ребёнок может **объяснить своими словами**, почему самим выбранное правило
   держится лучше навязанного.
3. Семья может **применить**: собрать, распечатать и подписать договор без
   аккаунта и без передачи данных наружу.
(Проверка: «покажи правило для родителей», «почему вы выбрали именно это?».)

## 5. Контент-план
Единица контента: Regel-Baustein (`{id, text}`) внутри категории. MVP: 3
обязательные категории × 6–8 правил в `daten/regeln.json`. Схема:
`kategorien[{id,name,emoji,regeln[{id,text}]}]`. Дидактический анти-шаблон-тест
(node:test): ровно 3 обязательные категории (kind/eltern/gemeinsam), в каждой
≥ 6 правил, каждое правило ≥ 20 знаков, уникальные id; правила для родителей —
обязательны (нельзя собрать «договор» из одних детских правил как норму жанра).

## 6. Политика соответствия (Pflicht, docs/02)
[x] Werbefrei / без покупок  [x] Без аккаунтов
[~] Персональные данные: осознанно допущены **только Vornamen сторон**, по
прямому заданию, как реквизит договора — с UI-предупреждением «только имена, без
фамилий/адресов» и, главное, **без сохранения имён** в localStorage (в отличие от
детских приложений, где действует «Kürzel max 3, keine Namen»: здесь это
приватный семейный документ, а не собираемые данные).
[x] Без внешних запросов (CSP `default-src 'self'` + installiereNetzwerkWaechter)
[x] localStorage: только черновик выбора `fmv.entwurf` + кнопка «Alle Daten löschen»
[x] Privacy by default (ноль запросов привилегий, print — локальная функция браузера)
[x] Mobile First 360px/48px (kinder-ui-классы)  [x] Vorlesen (интро + каждая категория)
[x] Offline после загрузки  [x] eltern.html (концепция + связь с takt-pause)
[x] Impressum/DSGVO (ссылка ../../impressum.html)
Особые риски темы: имена → не сохраняются, предупреждение в UI; тема
чувствительная (контроль в семье) → формулировки без запретительного тона,
«сначала выслушать», «Hilfe holen ist nie peinlich». AI Act: никакого скоринга/
рейтинга/сравнения детей — только сборка документа. Urheberrecht: из внешних
концепций взята лишь идея договора, все тексты правил написаны заново.

## 7. Стандарты и финансирование (Wofür)
Стандарты: UN-KRK ст. 12 (участие) · JuSchG/Gefährdungsatlas · DSGVO (ноль
передачи данных, имена не хранятся). Förder-Fit: BzKJ (Teilhabe, sichere
Voreinstellungen) — см. foerder-navigator. Multiplikator: раздаётся на
родительских вечерах (родня — «Elternabend-Kit», №24).

## 8. Аджайл-оценка
Aufwand: M (готовые паттерны: чекбокс-UI kriterien-check, print kita-wochenplaner,
kinder-ui, kinderschutz). Что переиспользуем: `el`/`vorlesen`, CSS kinder-ui,
NetzwerkWaechter, `druck.css`-паттерн. Первый срез (playable, готов в MVP): выбор
правил из 3 категорий + своё правило + имена + предпросмотр + печать с подписями.

## 9. Kindertest / Familientest-гипотезы
Что проверяем на 5–8 семьях: воспринимают ли дети правила для родителей как
настоящие обязательства (симметрия)? Понятен ли смысл «мы договорились», а не
«мне запретили»? Пользуются ли еженедельным пересмотром? Не пишут ли в свободное
поле лишние персональные данные (проверить действенность предупреждения)?
Достаточно ли 6–8 правил на категорию или нужны наборы под возраст 6–8 / 10–12?
